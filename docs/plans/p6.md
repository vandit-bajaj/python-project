# Phase 6 Plan — 3D Face View

## 1. Overview & Objective
Implement an approximate 3D face visualizer in DermaLens that reconstructs a smoothed 3D mesh from single-photo facial landmarks, maps the user's face texture and per-concern false-color heatmaps onto canonical UV space, and renders smoothly on mobile devices (≥ 30 FPS, DPR-capped, frame-on-demand, < 2.5MB lazy chunk).

---

## 2. Roadmap Requirements & Constraints

| Requirement | Implementation Strategy |
|---|---|
| **Canonical Mesh Topology** | Triangulated mesh derived from canonical 468 landmark coordinates with mouth and eye cavities cleanly clipped. |
| **Depth Smoothing** | Laplacian neighbor smoothing + smooth ellipsoidal facial volume prior to prevent single-photo depth spikes. |
| **Albedo & Heatmap Blending** | WebGL GLSL shader blending unwrapped face albedo texture with 2D concern heatmaps using the color-blind thermal palette (navy → amber → coral). |
| **Edge Fade** | Radial & geodesic boundary fade in fragment shader so mesh does not appear as a harsh cut-out cardboard mask. |
| **Touch Orbit Controls** | Azimuth strictly clamped to ±45° (single photo has frontal data only); polar clamped to [60°, 120°]; pinch zoom; double-tap reset. |
| **Tap Region Highlight** | GPU raycasting on tap to identify facial region (`forehead`, `cheeks`, `nose`, `chin`, etc.) and pulse active region. |
| **Mobile Performance** | DPR capped at `Math.min(devicePixelRatio, 2)`; frame-on-demand (renders only on orbit/zoom/slider input, 0 idle GPU usage); full resource disposal on unmount; WebGL context loss recovery. |
| **Lazy-Loaded Chunk** | Dynamic `next/dynamic` import with SSR disabled; zero impact on landing page initial JS bundle budget. |
| **Static Fallback & Notice** | Display banner: *"approximate 3D from a single photo"*. If WebGL2/WebGL is unsupported or lost, gracefully fallback to 2D `HeatmapCanvas`. |

## 3. Architecture & Task Breakdown

### Task 1: Mesh & Topology Generation (`packages/analysis-core/src/geometry/mesh.ts`)
- Implement `buildFaceMeshGeometry(landmarks, uvCoords, options)`:
  - Delaunay 2D triangulation across canonical face landmark UV space.
  - Cavity filtering: remove triangles falling inside eye contours and lip contours.
  - Boundary filtering: exclude triangles crossing the outer face boundary.
  - Smooth z-depth via 3-iteration Laplacian smoothing across triangle vertex adjacency.
  - Blend depth with subtle ellipsoidal cranial curvature prior: `z = (1 - w) * z_landmark + w * z_prior`.
  - Output typed Float32Arrays for `positions`, `normals`, `uvs`, and Uint16Array for `indices`.
- Add unit tests in `packages/analysis-core/tests/mesh.test.ts`.

### Task 2: Dependency Setup (`three` and `@types/three`)
- Install `three` (MIT) and `@types/three` (MIT) into `packages/ui` and `apps/web`.
- Verify permissive license check via `pnpm check:licenses`.

### Task 3: 3D Shader & Material (`packages/ui/src/components/Face3DViewer/material.ts`)
- Custom `THREE.ShaderMaterial` with:
  - `uniform sampler2D uAlbedo`: Base face texture.
  - `uniform sampler2D uHeatmap`: Concern heatmap.
  - `uniform float uOpacity`: Heatmap overlay blending weight (0.0 – 1.0).
  - `uniform float uEdgeFade`: Alpha falloff factor near boundaries.
  - `uniform vec3 uHighlightColor`: Selected region highlight tint.
  - `uniform float uHighlightIntensity`: Highlight blend factor.
- Precision set to `mediump` for mobile GPU efficiency.

### Task 4: Interactive 3D Component (`packages/ui/src/components/Face3DViewer/Face3DViewer.tsx`)
- Encapsulate Three.js scene, camera, renderer, and `OrbitControls`.
- Clamp azimuth: `minAzimuthAngle: -Math.PI / 4`, `maxAzimuthAngle: Math.PI / 4`.
- Clamp polar: `minPolarAngle: Math.PI / 3`, `maxPolarAngle: 2 * Math.PI / 3`.
- Frame-on-demand: render invoked on `controls.change` and prop updates, idle RAF stopped.
- Raycaster on tap: emits `onSelectRegion(regionId)`.
- Double-tap detection: smooth tween back to frontal camera orientation `(0, 0, 2.5)`.
- Context loss listeners: `webglcontextlost` and `webglcontextrestored`.
- Lifecycle disposal: traverse scene on unmount, dispose geometries, materials, textures, and renderer.

### Task 5: 3D View Integration in Report (`apps/web/src/app/report/page.tsx`)
- Add 2D / 3D toggle tab above the visualizer card:
  - `[2D Heatmap]` ⟷ `[3D Face Model]`.
- Dynamic import with `next/dynamic`:
  - `const Face3DViewer = dynamic(() => import('@dermalens/ui').then(m => m.Face3DViewer), { ssr: false, loading: () => <Face3DFallback /> })`.
- Shared state: concern selector chips and opacity slider synchronously control both 2D and 3D views.
- Prominent badge: *"approximate 3D from a single photo"*.

### Task 6: Testing & Mobile Verification
- Unit tests: verify mesh topology vertex count, valid index bounds, normal vectors, and depth smoothing stability.
- Playwright E2E: test 2D ⟷ 3D toggle, layer toggling, touch drag interaction, and WebGL fallback.
- Capture mobile screenshots at 390×844 and 360×800.
- Verify zero outbound network requests and permissive licenses.

## 4. Risks & Mitigations
- **Single-Photo Depth Distortion**: Raw single-photo landmarks lack true depth scans.
  - *Mitigation*: Laplacian adjacency smoothing plus gentle ellipsoidal prior ensures a cohesive, organic facial volume without spiky artifacts. Limited ±45° azimuth prevents viewing the unmodeled posterior.
- **Mobile GPU Overheating & Battery Drain**: Continuous rendering loops can throttle phones.
  - *Mitigation*: Frame-on-demand rendering only executes when user touches or adjusts controls; 0 FPS when idle. DPR capped at 2.0.
- **WebGL Context Eviction**: Backgrounding mobile browser tabs can lose WebGL context.
  - *Mitigation*: Handled via `webglcontextlost` prevention and automatic re-initialization on `webglcontextrestored`, with static 2D fallback.
